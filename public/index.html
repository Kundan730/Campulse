IMPACT / INCENTIVE LOOP

Reward fair reductions

Compare each benchmark building with its own recent baseline, normalized per occupant-day.

PROPOSED CREDIT RULE

Make the comparison fair

  • Compare the latest seven complete days with the prior 28 complete days for the same building.
  • Divide daily totals by estimated occupant-days; do not reward a quiet building for lower total use alone.
  • Use a provisional score of one point per percentage point of reduction, capped at 100, and award zero when use rises.
  • Do not issue credits until a phased pilot verifies occupancy and meter quality. Keep personal data out of scoring.
MEASURE WHETHER IT WORKS

Run a phased comparison

Match similar buildings, start credits in one group first, and compare normalized use before and after against a delayed-start group. Adjust for occupancy and academic calendar. Audit meter coverage and unusual reporting before awarding credits.

SCALE FROM 3 TO 30+

Keep the building edge simple

Each building publishes timestamped readings to a shared ingestion endpoint. At 30 buildings × four hourly telemetry channels, the campus receives about 120 channel readings per hour, plus configurable smart-bin events (3,000 per day at 100 per building). A shared MQTT broker and PostgreSQL time-series tables can absorb that rate with batched writes, partitioned retention and one configuration record per building. The prototype uses SQLite and a local process. Move the same record keys and schemas to PostgreSQL and add broker workers; the device and dashboard contracts stay the same.

FAILURE MODES

Detect and contain

  • Sensor drift: flag flat lines, impossible jumps and disagreement with manual checks; compare against a reference meter and recalibrate before adjusting operations.
  • Gateway outage: alert after three missed hourly arrivals, retain a stale building card, queue records locally, then reconcile by building ID and capture timestamp on reconnect.
  • Model degradation: track human overrides and per-class review rates by month; collect a small audited sample and retrain only after time-aware validation.
  • Incentive gaming: require meter completeness, use occupant-day normalization and audit sudden denominator changes before awarding any credits.
Software and shared infrastructure. Campulse uses open-source Node.js, SQLite and Python tooling, with no paid inference service. Production hosting, broker operations, campus network work, professional meter installation, maintenance and calibration are shared or site-specific costs outside the per-building hardware cap.
